How to use Union Alpha without overstating what worked

These are documentation-based instructions. The run attempted three OpenRouter and one OpenCode Go request with pre-existing credentials; all DNS-failed before HTTP/TLS, so neither path is claimed as successfully tested.

Before sending a prompt: use non-sensitive material only. OpenRouter’s anonymous-provider route says prompts/completions may be retained. “Not used for training” is not the same as no retention.

A. OpenRouter API

  1. Use a lawful existing OpenRouter API key. Do not create accounts/keys to evade limits.
  2. Send a small, non-sensitive request to POST https://openrouter.ai/api/v1/chat/completions with exact model stealth/union-alpha, Bearer authentication and JSON content type. S05
  3. Record UTC, settings, status, headers, response and latency. On a 429, preserve X-RateLimit-* / Retry-After, back off, and use an explicit fallback—do not retry-storm. S02
POST https://openrouter.ai/api/v1/chat/completions Authorization: Bearer $OPENROUTER_API_KEY Content-Type: application/json {"model":"stealth/union-alpha","messages":[{"role":"user","content":"hello"}]}

Limit boundary: the exact OpenRouter quota is unknown. Generic free-plan/free-model rules are not a published allocation for this slug. S01 · S04

B. OpenCode Go

  1. Install OpenCode using a documented method and satisfy its documented sign-in/subscription/API-key prerequisites. S07
  2. In the TUI, use /connect, choose OpenCode Go, provide the key, then use /models; select opencode-go/union-alpha. S06
  3. For the documented API route, use model union-alpha at https://opencode.ai/zen/go/v1/messages with the documented Anthropic-compatible client.

Limit and privacy boundary: Go lists “Unlimited” estimated requests/monthly limit only as a limited-time Go-route listing, not a tested capacity guarantee and not an entitlement for OpenRouter keys. Its table lists 0-day retention and no training use for that route. S06

What this run actually observed

At 2026-09-16T21:03:35Z, each of four non-sensitive request attempts ended at DNS resolution (EAI_AGAIN) before HTTP/TLS. There is no provider response, successful inference, rate-limit header, latency, availability or error conclusion.
